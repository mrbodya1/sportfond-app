# Локальное приложение на домашнем сервере

## Расположение

Windows D:\Projects\sportfond-app соответствует /mnt/d/Projects/sportfond-app в WSL.

- backend/ — исходный Python-код.
- runtime/data/app.sqlite3 — пользователи, сессии, согласия, тренировки и журнал.
- runtime/data/recognition.sqlite3 — кэш извлечённых показателей и лимит распознаваний.
- runtime/uploads/ — непубличные скриншоты; имена SHA-256 + расширение.
- runtime/backups/ — снимки данных и кода перед обновлением.
- runtime/app-server.log и runtime/app-server.pid — вывод и PID текущего процесса.

Приватные конфигурации: /var/lib/sentinelx/edit-test/sportfond-home/, каталог 0700, файлы 0600. Не копировать их в репозиторий.

- openai.env: OPENAI_API_KEY, необязательный OPENAI_MODEL.
- mail.env: SMTP_USERNAME, SMTP_PASSWORD. Текущий обработчик использует smtp.beget.com:465 с проверкой TLS.
- app.env: SESSION_SECRET (случайное значение минимум 32 символа), ADMIN_EMAILS (разрешённые почты через запятую).

Смена SESSION_SECRET завершает старые сессии и делает выданные коды недействительными. Значения ключей, паролей, кодов и cookie нельзя печатать в журнал.

## Запуск

```sh
python3 /mnt/d/Projects/sportfond-app/backend/app_server.py \
  --ai-env /var/lib/sentinelx/edit-test/sportfond-home/openai.env \
  --smtp-env /var/lib/sentinelx/edit-test/sportfond-home/mail.env \
  --app-env /var/lib/sentinelx/edit-test/sportfond-home/app.env \
  --data-dir /mnt/d/Projects/sportfond-app/runtime/data \
  --upload-dir /mnt/d/Projects/sportfond-app/runtime/uploads \
  --port 18766
```

Процесс слушает только 127.0.0.1. На Windows Vite по адресу http://127.0.0.1:4174 проксирует весь /api в WSL. Использовать именно этот origin: другие адреса отклоняются. Preview на порту 4175 сам по себе не проксирует API и предназначен для проверки статической сборки.

`recognition_server.py` и OPENAI-TEST.md — предыдущий изолированный обработчик распознавания, без пользовательских аккаунтов. Одновременно с новым app_server.py его не запускать: одинаковый порт. Старый кэш сохранён; app_server повторно применяет текущие правила к извлечённым данным.

## Поведение

Регистрация требует имени, email и двух отдельных отметок. SMTP отправляет код, сервер хранит только его HMAC. Код одноразовый, действует 10 минут, максимум 5 попыток. Не более 5 запросов в час на почту и 20 на локальный экземпляр сервера. Логин без существующего аккаунта предлагает регистрацию.

После входа браузер получает HttpOnly SameSite=Strict cookie с путём /api. Пока используется локальный HTTP; для публикации обязательны HTTPS и Secure-cookie. Срок сессии — 30 дней. Выход удаляет серверную сессию.

Администратор определяется по подтверждённому email из приватного ADMIN_EMAILS. Прямые обращения к административным API проверяются сервером. При новом устройстве администратор входит тем же способом по письму; универсального кода и обходного входа нет.

После распознавания запись сразу сохраняется: approved увеличивает зачёт, pending/rejected — нет. Подтверждение администратором нужно только pending или при исправлении решения. Результаты, исправления, удаление и восстановление меняют счётчики на сервере. Удаление мягкое; хеш не освобождается для повторного зачёта.

На экземпляр допускается одна одновременная проверка и до 10 новых распознаваний в час. Повторный файл берётся из кэша; уже сохранённая тренировка не отправляется повторно в OpenAI.

## Финальная проверка владельцем

1. Зарегистрироваться, самому принять правила и согласие, подтвердить почту. Проверить полученное имя и роль администратора.
2. Загрузить свою реальную пробежку с GPS после 29.10.2026 и нажать «Отправить». Проверить дату и километры, автоматический зачёт.
3. Обновить вкладку: история и сумма должны сохраниться. Тот же файл повторно не добавляет километры.
4. Удалить тренировку, проверить уменьшение суммы, восстановить через уведомление — сумма возвращается один раз.
5. Проверить неоднозначный результат, ручное решение и журнал. Обычный участник не должен видеть админку и чужие изображения.
6. Выйти и войти снова по новому письму. Проверить телефон и компьютер.

## Сохранность и публичный запуск

GitHub хранит исходный код, но не заменяет резервную копию участников. Снимок SQLite делать через sqlite3.Connection.backup, а изображения копировать в согласованный архив в тот же период; простое копирование открытой БД не использовать. Перед обновлением уже сохранён снимок старого кэша. Регулярное расписание и восстановление из архива ещё нужно подготовить до открытия регистрации публике.

Пока не настроены автозапуск после перезагрузки и публичная маршрутизация этого обработчика. Для выпуска нужны отдельный HTTPS API, Secure-cookie, корректный разрешённый origin, решение о сроках хранения и физическая проверка PWA. Публичную заглушку main не заменять автоматически.
