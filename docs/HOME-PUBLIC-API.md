# Домашний публичный API Sportfond

Подготовлено 14.11.2026. Это инструкция к текущей конфигурации; успешный публичный запуск подтверждать отдельно.

## Схема

GitHub Pages app.sportfondhm.ru → HTTPS api.sportfondhm.ru → роутер → Windows LAN → WSL Caddy → закрытый контейнер API → SQLite / OpenAI / SMTP Beget.

Домен и почта остаются в Beget, NS не меняются. В DNS нужен A api → публичный IPv4 домашнего подключения. Остальные записи сайтов и почты не заменять.

## Развёрнутые компоненты

Compose-проект sportfond-public-api: infra/home/compose.yaml, Caddyfile. На домашнем сервере /mnt/d/Projects/sportfond-app/infra/home/. Запуск:

```sh
docker compose -f /mnt/d/Projects/sportfond-app/infra/home/compose.yaml up -d
```

- api: Python, UID/GID 999:986 (совпадают с владельцем приватных файлов на этом хосте), read_only, без capabilities; сетевой порт 8080 только внутри Compose, диагностический порт хоста только 127.0.0.1:18767.
- https: Caddy, образ зафиксирован digest; 80/443; сертификаты в именованном caddy_data, настройки в caddy_config. Автоматический HTTPS требует корректного DNS и входящего доступа к этим портам. Не удалять тома при обычном обновлении.
- backup: согласованный снимок SQLite и изображений из этой БД раз в 86400 секунд. Архивы runtime/backups/snapshot-*/ содержат manifest.json с SHA-256. Старые снимки автоматически не удаляются; следить за свободным местом. Это локальная копия, не защита от утраты всего диска.

Все контейнеры имеют restart: unless-stopped. Это перезапуск при работающем Docker, а не гарантия старта Windows/WSL до входа пользователя или работы во время сна.

## Секреты

/var/lib/sentinelx/edit-test/sportfond-home/public/: app.env, openai.env, mail.env; файлы 0600, владелец sentinelx (999:986), каталог 0700. В контейнеры передаются только три нужных файла read-only, а не вся папка секретов. app.env содержит прежний SESSION_SECRET и ADMIN_EMAILS, плюс APP_PUBLIC_ORIGIN=https://app.sportfondhm.ru. Значения не помещать в GitHub.

В публичном режиме разрешён только Origin https://app.sportfondhm.ru; CORS credentials=true, без wildcard. Сессии HttpOnly, Secure, SameSite=Strict, host-only, Path=/api. Локальный старый процесс на 18766 использует прежнюю конфигурацию и остаётся отдельным контуром разработки.

## Windows и WSL

На момент подготовки: Windows LAN 192.168.1.7, WSL 172.22.191.85. Перед каждым применением перепроверять адреса. В роутере закрепить адрес компьютера через DHCP reservation; изменение IP WSL после перезапуска требует обновления portproxy.

Скрипт infra/home/Set-SportfondNetwork.ps1 предназначен для запуска владельцем с правами администратора. Он проверяет адреса и конфликты, сохраняет прежнюю таблицу portproxy, добавляет только TCP 80/443 на конкретный LAN-IP и правило брандмауэра с именем Sportfond API TCP 80 443. Другие перенаправления и VPN не меняет. Повторное применение при существующих правилах останавливается для ручной проверки.

```powershell
.\Set-SportfondNetwork.ps1 -ListenAddress 192.168.1.7 -WslAddress 172.22.191.85
```

Текущая сессия Codex не имеет административного токена Windows. Применение этого скрипта требует UAC/ручного запуска администратором. Не отключать firewall целиком, не использовать DMZ и не публиковать 18766/18767/8080.

## Роутер

Rotek RX-33412, HSI/ppp0, WAN подтверждён ранее как 94.50.96.146. Предполагаемые новые правила: TCP внешний/внутренний 80 → 192.168.1.7:80 и TCP 443 → 192.168.1.7:443. Не включать UDP и диапазоны дополнительных портов.

Глобальный режим перенаправления был выключен, в таблице есть 10 старых записей uTorrent/Tailscale. Их список сохранён отдельно в рабочей папке network-backups/router-ports-before-2026-11-14.txt. Для удаления старых записей и нового публичного доступа запрошено отдельное подтверждение владельца. Не активировать старые записи по ошибке.

## Проверки перед признанием запуска завершённым

1. api.sportfondhm.ru разрешается в выданный IPv4 без конфликтующего AAAA/CNAME.
2. Windows portproxy и firewall настроены, роутер пробрасывает только согласованные порты.
3. Caddy получил публично доверенный сертификат; не обходить ошибки TLS и не использовать -k в приёмке.
4. /api/health доступен извне по HTTPS, HTTP перенаправляется на HTTPS.
5. При включённом VPN ответы внешнему клиенту возвращаются правильно. Paper VPN нельзя отключать автоматически; при асимметрии маршрутов согласовать раздельную маршрутизацию.
6. Публичная регистрация/вход через Beget работает; правильный admin email имеет роль, другой аккаунт не видит админку/чужие файлы.
7. Реальная тренировка, повторная загрузка, обновление страницы, удаление/восстановление и счётчики проверены.
8. Проверено восстановление резервной копии; отдельно согласован внешний архив и запуск после перезагрузки компьютера.

## Откат

Остановить только sportfond-public-api; не удалять тома Caddy и runtime. В роутере отключить новые правила, вернуть DNS api при необходимости. Для отката Windows удалить только именованное правило Sportfond API TCP 80 443 и portproxy на LAN-IP 80/443; существующее Tailscale-перенаправление 2222 не трогать. Локальная версия 127.0.0.1:4174 и её данные сохраняются.


## Фактическое состояние после применения правил

Владелец запустил скрипт в PowerShell администратора. Выяснилось, что Docker Desktop уже слушает 80/443 через com.docker.backend; скрипт скорректирован, чтобы использовать эти порты и добавить только именованное правило firewall. Новый portproxy не добавлен, старое Tailscale-перенаправление 2222 сохранено. Существующая политика запуска скриптов Windows не менялась: применялся параметр ExecutionPolicy только к одному дочернему процессу.

В роутере сохранены Sportfond-HTTP и Sportfond-HTTPS: 192.168.1.7, TCP, внутренние/внешние 80 и 443, ppp0. Ручное перенаправление включено. Старые строки в общей таблице оказались динамическими UPnP-правилами: попытки удаления через ручную форму не удалили их. Это отдельно подтверждено страницей UPnP. Служба UPnP оставлена без изменений, отключение других устройств не выполнялось.

HTTPS-прокси локально отвечает 308 с перенаправлением на api.sportfondhm.ru; API отвечает 200. Проверка HTTP через публичный IP из текущего VPN-соединения завершилась тайм-аутом. Это не доказательство внешней доступности; запрошена независимая проверка с мобильной сети. TLS-сертификат не выпущен: Caddy сообщает NXDOMAIN для api.sportfondhm.ru. Владелец сообщил, что Beget снова недоступен из-за технических работ, DNS пока не изменён.

OpenAI из контейнера достигается через VPN (неавторизованный запрос возвращает ожидаемый 401). SMTP Beget в текущем сетевом маршруте не прошёл проверку: SSL 465 тайм-аут на всех полученных A-адресах; STARTTLS 2525/587 не завершился. Настройки почты и пароли не заменялись; не использовать нешифрованную отправку как обход.

Первоначальный автоматический запрос записи подготовки в main отклонён проверкой из-за старого требования maintenance; применён разрешённый вариант сохранения в recovery. Публичный фронтенд остаётся в main. Не обходить этот отказ альтернативным способом записи main.

Независимая проверка владельца с мобильной сети: публичный IP не загружается. Локальный HTTP 308 и firewall повторно подтверждены. Основной маршрут Windows проходит через Paper VPN; ожидается диагностический повтор с временно отключённым владельцем VPN. Причина внешнего тайм-аута пока не установлена.
