## Безопасный тест

Скрипт backend/check_mail.py запускается только на сервере с Python 3. Секреты вводятся в серверное окружение безопасным способом, не через форму сайта и не в GitHub. Переменные SMTP_HOST=smtp.beget.com, SMTP_PORT=465, SMTP_USERNAME (полный адрес), SMTP_PASSWORD, SMTP_FROM (по умолчанию равен логину). Секреты не передавать в аргументах команды и не выводить в журнал.

```sh
python3 backend/check_mail.py
python3 backend/check_mail.py --mode auth
# Только после согласования конкретного адреса для одного тестового письма:
python3 backend/check_mail.py --mode send --to recipient@example.com
```

Без --mode send письмо не отправляется. Скрипт не проверяет входящие и не меняет DNS/пароль. Тесты: python3 -m unittest discover -s backend -p test_mail.py.

Настройки Beget: https://beget.com/ru/kb/how-to/mail/nastrojka-pochty-na-mobilnyh-ustrojstvah

## Что требуется для настоящей регистрации

В браузере пока только демонстрация с кодом 123456. Для запуска нужны серверные маршруты запроса/подтверждения кода, стойкий случайный одноразовый код с ограниченным сроком, хранение его хеша, ограничение попыток и частоты отправки, одинаковые ответы для защиты списка ящиков, серверные сессии и безопасные cookie. Секреты SMTP не попадают в клиентский код. Общие данные участников хранятся в БД сервера, а не в памяти браузера.

Согласие на данные оформляется отдельно от правил; фиксируются версия, время и факт подтверждения на сервере. Идентификатор версии документа не заменяет юридическую проверку. Полные реквизиты оператора, даты и условия проекта пока не предоставлены.

Админка /#admin — открытый демонстрационный интерфейс с вымышленными записями. Скрытие ссылки или проверка роли в JavaScript не защищают доступ. Реальный API обязан проверять сессию и роль при каждом чтении/изменении, выдавать изображения только авторизованно, защищаться от CSRF и писать журнал действий. Ни одного рабочего административного API сейчас нет.
