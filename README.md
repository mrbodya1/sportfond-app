# Sportfond App — восстановление интерфейса

Ветка recovery: новый адаптивный прототип. Основная ветка main и её заглушка не изменены.

## Запуск

Node.js 20.19+ или 22.12+ и npm:

```sh
npm install
npm run dev -- --host 127.0.0.1 --port 4174
```

Открыть http://127.0.0.1:4174/

Страницы: /#home, /#registration, /#account.
Сборка: npm run build. Статические файлы находятся в dist/client.
Проверки подготовленного Sites runtime: npm run test:sites.
Для GitHub Pages публикуется только dist/client, а не dist/server.

## Демонстрационный режим

Форма принимает имя, email и согласие, затем показывает код 123456. Письмо не отправляется. Кабинет содержит явно обозначенные примерные данные. Загрузка проверяет тип и размер до 5 МБ, показывает изображение локально. Изображения, имя и email не отправляются на сервер и не сохраняются после перезагрузки. Это не настоящая авторизация.

## Следующие этапы

1. Защищённый серверный вход по email-коду, ограничения запросов и сессии.
2. Авторизованная загрузка изображений: серверная проверка формата и размера, хранение вне публичного каталога, сроки удаления.
3. Вызовы OpenAI/GigaChat только с сервера. Ключи — в серверном окружении вне GitHub и браузера.
4. Очередь распознавания, ручная модерация, база тренировок, общий прогресс и таблица.
5. Полные правила, политика данных и доступный preview перед заменой заглушки.

## Дизайн

Утверждённые макеты: ../design/app-v1 в рабочей папке. Палитра #1E3A8A, #3B82F6, #22D3EE, #F8FAFC. Montserrat и Open Sans поставляются локально через Fontsource; иконки Phosphor. Фон и растровый логотип подготовлены по предоставленным материалам. Ширины проверяются от 320 px; на широких экранах форма и кабинет используют колонки.

Не переключать GitHub Pages с main на recovery: текущая публичная заглушка должна оставаться до готовности приложения. CNAME наследуется от main, но эта ветка не публикуется автоматически.
## Проверенные варианты
- Ширины 320, 390, 768 и 1440 px.
- Компьютер: двухколоночная форма и кабинет. Телефон: один столбец, нижняя навигация.
- Регистрация/вход демонстрационные, без запросов к API.
- Последняя тренировка и километры — примеры.

## Новые разделы

- /#admin — открытая демоадминка: фильтры, поиск, изменение зачётной дистанции, подтверждение/отклонение с причиной, участники и журнал изменений в текущей сессии. Рабочих административных API нет.
- /#rules — проект правил участия.
- /#privacy — проект политики обработки данных.
- /#consent — отдельный проект согласия.

В форме регистрации две независимые отметки, изначально снятые. Все юридические документы требуют реквизитов оператора и окончательных условий до реального запуска. Почта и план регистрации описаны в docs/MAIL-AND-REGISTRATION.md. SMTP-диагностика и её тесты находятся в backend; это не сервер авторизации.

## Документы от владельца, 13 ноября 2026

Политика и согласие заменены предоставленными текстами без редакторских изменений. Источники: src/legal/policy.md и src/legal/consent.md. Реквизиты оператора предоставлены владельцем; это не результат юридического аудита.

Канонические пути /policy/ и /consent/ работают в локальной версии и создаются как статические страницы в dist/client при npm run build. Hash-адреса #privacy и #consent совместимы. Ссылки из регистрации открывают документы в новой вкладке, сохраняя введённую форму. Основной сайт и его заглушка не изменены.

SMTP Beget: авторизация и приём тестового письма сервером проверены, получение подтверждено владельцем. Регистрация и фиксация согласия в БД ещё не реализованы.


## Завершение фронтенда: правила, история, PWA

Переработанные правила: src/legal/rules.md. Сохранены условия владельца: бег на улице с GPS, дорожка/помещение с пульсом, топ-3 — слоты, места 4–10 — скидка 20%, дополнительный розыгрыш 1 слота и 10 скидок. Даты зачёта, возраст, числовые пороги и конкретное мероприятие ещё надо объявить. Изменённый документ требует проверки владельцем перед официальным запуском.

Разделы /#history и /#leaderboard работают с общей демонстрационной моделью: подтверждённая дистанция пересчитывается после модерации, удаления и восстановления. Новые примеры из загрузки попадают в очередь /#admin; выбранное изображение можно увеличивать. Реальная загрузка и ИИ не вызываются. Показатели примера не извлекаются из изображения. Все изменения существуют только в памяти вкладки, до перезагрузки.

Вход: состояние ожидания, повторный запрос с паузой 60 секунд, срок примера кода 10 минут, пять попыток, пример истечения сессии через профиль. Это UX-демонстрация, не защита доступа. Настоящие ограничения должны обеспечиваться сервером.

PWA: manifest, иконки 192/512/180, maskable-иконка, инструкция установки iPhone/Android, версия офлайн-кэша и уведомление об обновлении. Service worker подключается только в production-сборке. Не кэширует API, POST, загрузки и сторонние запросы; в кэше только перечисленная статическая оболочка. Обновление применяется по нажатию с предупреждением о сбросе демоданных. При изменении логики runtime пересмотрите стратегию кэширования.

Проверка сборки:

```sh
npm run build
node --test tests/sites-worker.test.mjs tests/pwa.test.mjs
```

Локальная разработка: http://127.0.0.1:4174/. Проверка собранной PWA: npm run preview -- --host 127.0.0.1 --port 4175.

PWA проверена как сборка и интерфейс. Установка на настоящие iOS/Android и работа после сетевого отключения на физических устройствах остаются проверкой перед запуском. Установка зависит от возможностей браузера. Справка: https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/How_to/Trigger_install_prompt

Следующий этап — реальный серверный вход, БД, проверка прав администратора, распознавание, журнал, согласия с версиями документов и резервное копирование. Основная публичная заглушка не заменена.
